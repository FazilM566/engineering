## 2. Структура проекта

Проект организован в следующей структуре:

- `pyproject.toml` – зависимости и настройки проекта (используется `uv`)
- `uv.lock` – точный снимок зависимостей
- `report.md` – отчёт с экспериментами и выводами
- `self-checklist.md` – чеклист самопроверки
- `notebooks/` – экспериментальные ноутбуки (EDA, прототипы моделей)
- `src/` – основной код проекта:
  - `data/` – подготовка данных (`prepare.py`, `load.py`)
  - `models/` – определение модели и функции обучения (`model.py`, `train.py`)
  - `service/` – FastAPI‑сервис и CLI (`api.py`, `core.py`, `cli.py`)
  - `utils/` – вспомогательные функции (seed, device, управление заморозкой)
  - `train.py` – точка входа для двухэтапного обучения
  - `evaluate.py` – оценка модели на тестовой выборке
- `configs/` – конфигурационные файлы:
  - `inference_config.json`
  - `training_config.json`
  - `.env.example` – шаблон переменных окружения
- `data/` – содержит только `README.md` с инструкцией по получению данных
- `tests/` – тесты (`test_basic.py`)
- `artifacts/` – графики обучения, матрица ошибок и сравнительная таблица моделей.

## 4. Как запустить проект

- Вариант А (рекомендованный): Файл с обученными весами (`best_model_full.pth`) не включен в репозиторий из‑за большого размера. Предлагается:
   - скачать готовые веса по ссылке: [best_model_full.pth](https://drive.google.com/file/d/1VTad17j2F0hSf-5GcNdJSp-qXkNkSFEc/view?usp=drive_link)
   - положить файл в папку `artifacts/weights/` (создайте её, если отсутствует).
   - выполнить пункт 4.2
- Вариант Б: Если вы хотите обучить модель самостоятельно – выполните пункты 4.0, 4.1 и 4.2 последовательно.

### 4.0. Подготовка данных

Скачайте датасет с Kaggle(см. пункт 5) и распакуйте в любую папку.

Выполните скрипт подготовки:

```bash
uv run python -m src.data.prepare --input /путь/к/распакованной/папке --output data/processed
```

### 4.1. Запуск обучения модели

```bash
uv run python -m src.train --data data/processed
```
### 4.1.1. Оценка модели на тесте

```bash
uv run python -m src.evaluate --data data/processed --model artifacts/weights/best_model_full.pth
```
### 4.2. Запуск сервиса

```bash
uv run uvicorn src.service.api:app --reload --port 8000
```

Сервис доступен по адресу [http://127.0.0.1:8000](http://127.0.0.1:8000), документация Swagger – [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

Эндпоинты:

- GET /health – проверка состояния.

- POST /predict – загрузка изображения (multipart/form-data), возвращает предсказание.

Пример запроса через curl:

```bash
curl -X POST "http://127.0.0.1:8000/predict" -F "file=@/path/to/chest_xray.jpg"
```
### 4.3. Использование CLI (командная строка)

После того как модель получена (вариант А) или обучена (вариант Б), можно сделать предсказание для одного изображения через CLI:

```bash
uv run python -m src.service.cli "путь_к_изображению"
```

### 4.4. Получение справки

Если вы не уверены, какие аргументы требуются для любой команды, используйте флаг --help:

```bash
uv run python -m src.data.prepare --help
uv run python -m src.train --help
uv run python -m src.evaluate --help
uv run python -m src.service.cli --help
```

## 8. Ограничения и дальнейшая работа

**Текущие ограничения:**
- Сервис обрабатывает только одно изображение за запрос (пакетная обработка не реализована).
- Отсутствует аутентификация и авторизация; логирование ограничено стандартным выводом uvicorn.
- Тесты покрывают только базовую функциональность (создание модели, определение устройства); интеграционные тесты API не реализованы.

**Перспективы улучшения:**
- **Модель:** эксперименты с ансамблями (ResNet‑50 + Swin‑T) для повышения точности; поддержка выбора модели через конфигурационный файл.
- **Сервис:** добавление пакетного эндпоинта, кеширование результатов, поддержка GPU/CPU через переменную окружения.
- **Надёжность:** расширение тестов (интеграционные тесты API, нагрузочное тестирование), внедрение более детального логирования (например, через `logging`).
- **Развёртывание:** упаковка в Docker, деплой на облачную платформу (например, Heroku, AWS, Yandex Cloud).
