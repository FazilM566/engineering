## 1. Паспорт проекта

- **Название проекта:** `Ренгенография грудной клетки`
- **Автор:** `<Меликов Фазиль Гусейнович>`

- **Контакт:** `<@fazilmelikov>`

Проект посвящён построению сервиса классификации рентгеновских снимков грудной клетки по четырём классам: COVID, Lung opacity (непрозрачность лёгких), Normal, Viral Pneumonia. Реализован полный пайплайн: от подготовки открытого датасета до HTTP‑сервиса на FastAPI. Проведены эксперименты с простыми свёрточными сетями (SimpleCNN) и трансферным обучением (ResNet‑50, Swin‑T). Финальная модель – ResNet‑50 – достигла точности 96.78% на тестовой выборке и используется в сервисе..

## 2. Постановка задачи и контекст

Опишите:

1. **Предметную область и задачу:**
   - В условиях пандемии COVID‑19 автоматический анализ рентгеновских снимков грудной клетки помогает врачам быстрее выявлять признаки вирусных поражений. Цель проекта – разработать сервис, который по загруженному снимку возвращает вероятный класс заболевания. Потенциальные пользователи – медицинские работники для предварительной диагностики или системы скрининга.

2. **Формулировку задачи в терминах ML/ИИ:**
   - Входные данные: изображение рентгеновского снимка (размер 224×224 пикселя, RGB, нормализация по статистике ImageNet).  
   - Целевая переменная: один из четырёх классов: COVID, Lung opacity, Normal, Viral Pneumonia.  
   - Ограничения: необходимо обеспечить низкую задержку инференса (менее 100 мс на CPU) и воспроизводимость экспериментов.

3. **Целевые метрики качества:**
   - Accuracy – доля правильно классифицированных изображений (основная метрика сравнения).  
   - Confusion matrix – для анализа типичных ошибок (например, путаница классов Lung opacity и Normal).

## 3. Данные

Опишите, какие данные использует проект:

1. **Источник данных:**
Использован открытый датасет с Kaggle: [Balanced Augmented COVID‑CXR Dataset](https://www.kaggle.com/datasets/tr1gg3rtrash/balanced-augmented-covid-cxr-dataset).  
Датасет содержит 4 папки классов (COVID, Lung opacity, Normal, Viral Pneumonia) без предварительного разделения на train/val/test

2. **Структура данных:**
   - Исходные данные – изображения в формате .jpg, .png.  
   - После распаковки получено около 1.13 ГБ данных.  
    - Скриптом `src.data.prepare` данные разбиваются на train (70%), val (15%), test (15%) с фиксированным seed=42 для воспроизводимости. Подготовленная структура лежит в `data/processed/`.

3. **Предобработка и EDA:**
EDA выполнена в ноутбуке `notebooks/full.ipynb`:
- Отображены примеры изображений каждого класса.
- Подсчитано количество изображений в классах – классы сбалансированы.
- Для обучения применены аугментации: `RandomResizedCrop`, `RandomHorizontalFlip`, нормализация (mean/std ImageNet).  
- Для валидации и теста – только `Resize(256) → CenterCrop(224)` и нормализация.

Основные наблюдения: классы хорошо сбалансированы, качество снимков достаточное для обучения глубоких моделей.

## 4. Модели и подходы

Опишите, какие модели вы пробовали и как развивался ваш подход:

1. **Базовые (baseline) модели:**
    - SimpleCNN – собственная свёрточная сеть из трёх блоков (conv–pool) и классификатора.  
    - Обучена с нуля без аугментаций: точность 82.5%** на валидации.  
    - Обучена с аугментациями: точность выросла до 88.6%, но всё ещё отстаёт от трансферного обучения.
2. **Улучшенные модели и эксперименты:**
Использована стратегия двухэтапного fine‑tuning (как в ноутбуке):
- Этап 1: заморожен весь backbone, обучается только новый классификатор (fc).  
- Этап 2: разморожен слой `layer4` и классификатор, обучение с пониженной скоростью.

ResNet‑50 (выбрана как финальная)
- Архитектура: ResNet‑50 с ImageNet‑весами, заменён последний слой на 4 класса.  
- Гиперпараметры:  
  - Этап 1: LR = 1e-3, 15 эпох, оптимизатор Adam.  
  - Этап 2: LR для layer4 = 1e-4, для fc = 1e-3, 10 эпох, weight decay 1e-4.  
- Результат: валидационная точность 96.40%, тестовая 96.78%.

Swin‑T (экспериментально)
- Архитектура: Swin Transformer (tiny) с ImageNet‑весами.  
- Та же стратегия двухэтапного обучения.  
- Результат: валидационная точность 95.38%, время обучения и инференса больше, чем у ResNet‑50.

## 5. Экспериментальный протокол и результаты

Здесь важно показать, что выбор финальной модели был осмысленным.

1. **Экспериментальный протокол:**
- Данные разделены на train/val/test один раз скриптом `prepare.py`.  
- Все эксперименты проводились с фиксированным seed=42.  
- Метрики accuracy и confusion matrix вычислялись на валидационной и тестовой выборках.

2. **Сравнение моделей по метрикам:**

   | Модель / конфигурация                        | Валид. acc | Тест. acc | Комментарий |
   |----------------------------------------------|------------|-----------|-------------|
   | SimpleCNN (без аугментаций)                  | 82.5%      | –         | baseline    |
   | SimpleCNN (с аугментациями)                  | 88.6%      | –         | улучшение   |
   | ResNet‑50 (двухэтапное fine‑tuning)          | 96.40%     | 96.78%    | финальная   |
   | Swin‑T (tiny, двухэтапное fine‑tuning)       | 95.38%     | –         | медленнее   |

3. **Выбор финальной модели:**

ResNet‑50 выбран как финальная модель благодаря:
- Наивысшей точности (96.78% на тесте, против 95.38% у Swin‑T).  
- Меньшему времени инференса и простоте развёртывания.  
- Стабильности обучения и доступности предобученных весов.
Из confusion matrix (см. ноутбук) типичные ошибки:  
- Lung opacity ↔ Normal (58 ошибок),  
- Normal ↔ Lung opacity (31 ошибка),  
- единичные ошибки между другими классами.

## 6. Архитектура решения и сервис

Опишите, как из модели получился работающий сервис:

1. **Архитектура пайплайна:**
Подготовка данных – `src.data.prepare.py` (один раз) → `data/processed/`.  
Обучение – `src.train.py` вызывает `create_loaders`, создаёт модель, выполняет двухэтапное обучение, сохраняет лучшие веса в `artifacts/`.  
Инференс – `src.service.core.predict_from_bytes` загружает модель (кеширование через `lru_cache`), выполняет трансформации и возвращает предсказание.  
HTTP‑сервис – FastAPI в `src.service.api.py` предоставляет эндпоинты `/health` и `/predict`.  
CLI – `src.service.cli.py` позволяет предсказывать из командной строки.

2. **API и endpoints:**
- `GET /health` – проверка состояния сервиса (возвращает `{"status": "ok"}`).  
- `POST /predict` – принимает изображение (multipart/form-data), возвращает JSON:
  ```json
  {
    "prediction": "COVID",
    "confidence": 0.9987,
    "probabilities": {"COVID": 0.9987, "Lung opacity": 0.0004, ...},
    "latency_ms": 42.5
  }

3. **Технологический стек:**
- Язык: Python 3.11
- Управление зависимостями: uv (pyproject.toml, uv.lock)
- ML фреймворки: PyTorch, torchvision
- Веб‑фреймворк: FastAPI, uvicorn
- CLI: Typer
- Тестирование: pytest
- Конфигурация: JSON + .env.example

## 8. Ограничения и дальнейшая работа

Текущие ограничения
- Сервис обрабатывает только одно изображение за запрос (нет пакетной обработки).
- Отсутствует авторизация и расширенное логирование (только консоль).
- Модель работает на CPU (можно переключить на GPU через переменную DEVICE).
- Тесты покрывают только базовую функциональность (модель и устройство).

Дальнейшие улучшения
- Модель: попробовать ensemble (ResNet‑50 + Swin‑T) для повышения точности.
- Сервис: добавить кэширование результатов, поддержку GPU, асинхронную обработку.
- Тесты: интеграционные тесты API, нагрузочное тестирование.
- Развёртывание: упаковка в Docker, деплой на облачную платформу.
